# 대회 당일 운영 순서 (OPERATIONS)

> ⚠ **초안 — 리허설 전.** 이 문서는 아직 **실제 리허설로 검증되지 않았다.** 순서·타이밍은
> 대회 전 초기화 리허설(→ [ROADMAP](ROADMAP.md) "실제 수업 전 필수")에서 확인·수정해야 한다.
> **개발 DB가 곧 대회 DB다**(분리된 개발 프로젝트 없음) — 초기화 실수가 실전에 그대로 남는다.

관련: 게임 규칙 [GAME_RULES.md](GAME_RULES.md) · 데이터 교체 [DATA_GUIDE.md](DATA_GUIDE.md) · 화면 [SCREENS.md](SCREENS.md).

## A. 사전 준비 (대회 전날/직전)

1. **콘텐츠 확정** — 종목·주가·재무·힌트가 최종본인지 확인. 바꿨다면 DATA_GUIDE §2로 재생성·적용.
   `npm test`(정합성 68개)와 `node scripts/verify_game.mjs --yes`(5라운드 실 DB)가 **전부 통과**해야 한다.
2. **관리자 비밀번호 강화** — 현재 개발용 기본값은 약하다(값은 `.env` 참조, 문서엔 안 적는다). 실전용 강한 값으로 **DB와 `.env`를 동시에** 바꾼다.
   - DB: Supabase SQL Editor에서 `select private.set_admin_secret('새_강한_비밀');` 1회 실행.
   - `.env`: `VITE_ADMIN_PASSWORD`를 같은 값으로. **두 값이 어긋나면 관리자 로그인이 막힌다.**
   - (비밀은 git·마이그레이션에 절대 넣지 않는다.)
3. **게임 리셋** — 관리자 [진행] 탭 → **[게임 리셋]**(RESET 입력). 또는 `reset_game`.
   거래·보유·힌트·속보가 지워지고 R0(시작 전)으로 돌아간다.
4. **검증용 조 삭제** — `TEST-01`·`TIGER-03` 등 테스트 조를 [조 관리] 탭에서 삭제.
   **안 지우면 학생 리더보드에 테스트 조가 보인다.**
5. **실제 조 생성** — [조 관리] 탭에서 조를 추가하고 참가 코드·시드머니를 정한다.
   **시드 변경은 시작(R0) 전에만** 가능하다. 각 조에 코드를 배부.
6. **최종 점검** — 학생 화면(`/`)에 테스트 흔적이 없는지, 종목/가격/재무가 맞는지 직접 눈으로 확인.
   교육장 와이파이에서 Supabase 접속이 되는지 실기기로 확인(배포 위치는 미정 — [ROADMAP]).

## B. 당일 진행 순서

> 게임 루프는 GAME_RULES §1과 같다. 관리자는 [진행] 탭에서 조작한다.

1. **입장 확인** — 학생들이 참가 코드로 로그인. 관리자 [리더보드]/[조 관리]에서 전원 접속 확인.
2. **R1 시작** — [연도 넘기기]로 R1(2020)을 연다(0→1, **힌트 없음**). → **[타이머 시작]**(분 지정, 기본 10)
   으로 거래 창을 연다. 학생 즉시 매매. 10분 뒤 자동 마감.
3. **라운드 반복 (R2~R5)** — 매 라운드:
   - **[연도 넘기기]** → 다음 연도 가격 공개 + 순위 변동 + (R2~) **힌트 자동 배분**.
   - **[리더보드]로 순위 변동을 학생에게 보여준다**(큰 글씨 모드). 힌트 배분 경고가 있으면 확인.
   - **[타이머 시작]** → 거래. 마감까지 대기.
   - *필요하면* [진행] 탭에서 **공통 속보** 발송.
4. **최종 라운드 매매까지 끝나면** → **[대회 종료]**.

## C. 종료 절차

1. **[대회 종료]** — `admin_end_game`. 최종 연도(2025) 가격이 공개되고 최종 정산된다.
   전 학생 화면에 **대회 종료 모달**(최종 순위·자산·수익률 + 전체 순위표)이 자동으로 뜬다.
2. **시상/복기** — [리더보드] 큰 글씨 모드로 최종 순위 발표. 힌트·재무를 되짚어 판단 과정 복기.
3. **뒷정리** — 다음을 위해 데이터를 남길지 정한다. 다시 쓰려면 [게임 리셋]으로 초기화(테스트 흔적 방지).

## D. 알려진 트러블슈팅

- **RPC를 바꿨는데 "함수를 찾을 수 없다"** — PostgREST 스키마 캐시 때문이다. 마이그레이션/함수 변경 후
  REST에 반영되기까지 **약 20초** 걸린다. 잠시 기다렸다 새로고침.
- **관리자 기능이 전부 `unauthorized`** — DB `private.config`의 비밀과 `.env`의 `VITE_ADMIN_PASSWORD`가
  다르거나, 새 DB라 비밀이 아직 설정 안 됨(fail-closed). A-2로 맞춘다.
- **[타이머 시작]을 눌렀는데 학생이 매매 안 됨** — 라운드가 R0(시작 전)이면 타이머가 안 열린다.
  먼저 [연도 넘기기]로 라운드를 1 이상으로. 또는 이미 마감(`round_ends_at` 지남) → 다시 시작.
- **거래가 갑자기 잠김** — 타이머 만료(정상). 다음 라운드로 넘기거나 타이머를 다시 연다.
  마감 뒤 거래는 서버가 거부(`round_closed`)하므로 콘솔로도 안 뚫린다.
- **시드(seed.sql)만 다시 넣고 싶다** — `db push --include-seed`는 **새 마이그레이션이 없으면 시드를 건너뛴다.**
  Management API로 `supabase/seed.sql`을 직접 실행해야 한다(`SUPABASE_ACCESS_TOKEN` 사용, `.env` 참조).
- **순위가 안 바뀐다** — 정상이다. 라운드 중엔 전 거래가 같은 가격이라 평가금액이 안 변한다.
  순위는 **[연도 넘기기]로 가격이 바뀔 때만** 움직인다.
- **세로 화면에 "돌려주세요"만 보임** — 태블릿을 가로로. 세로(1023px↓)는 지원하지 않는다.
