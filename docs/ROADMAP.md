# 로드맵

지금 어디까지 왔고 뭐가 남았는지. 상태가 바뀌면 갱신한다.

**현재 위치: 프로토타입 동작.** 학생 화면 · 관리자 화면 · 서버 · 실시간이 전부 연결돼 돌아간다.
브라우저 2개 + 관리자 1개 풀 시나리오 31건 통과.

> ⚠ **아직 실제 수업에 쓸 수 없다.** 종목 데이터가 검증되지 않았고, 관리자 비밀번호가 개발용이며,
> 개발 흔적이 대회 DB에 남아 있다. 아래 "실제 수업 전 필수" 참고.

## 완료

### 백엔드 (Supabase, 프로젝트 `cufic_wts`)

- **스키마** — `game_state` / `stocks` / `teams` / `positions` / `trades` / `round_snapshots` /
  `order_sheets` / `hints` / `hint_grants` / `signals`. 마이그레이션 12개
- **RLS** — 읽기만 선별 허용, 쓰기 정책 없음(= RPC로만). `teams` 직접 조회 차단(참가 코드 비공개),
  힌트는 지급받은 조만 RPC로 조회
- **주문서 RPC** — `save_order_sheet`(시트 통째 교체·검증) / `advance_round`(일괄 체결, 한 트랜잭션) /
  `get_my_order_sheet`. 자금 규칙은 `order_funds_ok()` 한 줄로 분리
- **힌트 RPC** — `admin_list_hints` / `admin_upsert_hint` / `admin_grant_hints` / `get_my_hints`
- **관리자 RPC** — 전체가 `p_admin_secret` 필수. 비밀은 `private` 스키마(REST 경로 없음),
  미설정 시 fail closed
- **실시간** — `signals` 테이블 + Realtime. 신호를 받으면 각자 RPC로 재조회
- **검증** — RPC 실제 호출 62건 + 관리자 보호 26건

### 학생 화면

- 참가 코드 로그인(서버 검증) · 새로고침 자동 재로그인 · 로딩/실패/오프라인 처리
- **주문서** — 종목별 매수/매도 수량, 전 종목 합계, 체결 후 예수금 미리보기, 비율 버튼
- **힌트** — 등급 배지(S~D), 내 조에 지급된 것만, 도착 토스트(탭하면 카드로)
- 차트(종목별 결정론적 캔들·추세선 그리기) · 재무제표(연도 스포일러 차단) · MY 4탭 · 조별 순위
- 라운드 전환 요약 모달 · 다크/라이트 · 태블릿 대응(44px, 회전 안내)

### 관리자 화면 (`/?admin=1`)

- **진행** — 라운드 진행(확인 모달) · 대회 종료 · 리셋(RESET 입력) · 주문서 제출 현황(실시간)
- **힌트** — 라운드별 풀 관리 · 조별 지급 · 하위권/랜덤 배분 **제안**(강사가 확정) · 지급 이력
- **조 관리** — 추가/삭제 · 시드 설정(시작 전만) · 예수금/평가금액/수익률/제출 여부
- **종목·가격** — 연도별 가격 인라인 편집 · 0=거래정지 · 소급 안 됨 경고
- **리더보드** — 순위 변화(▲▼) · 큰 글씨 모드(프로젝터)

### 품질 장치

- **Vitest 66개** — 계좌 파생 · 데이터 정합성(힌트↔주가 전수 대조) · 과거 버그 4건 회귀
- `seed.sql`은 `src/data.js`에서 생성 — 정합성 테스트와 DB의 원천이 하나
- git — 의미 단위 커밋. `.env` 커밋 차단

## ⚠ 실제 수업 전 필수

1. **종목 데이터 교체** — 지금은 실제 종목명에 **검증되지 않은** 주가·재무. 학생이 지어낸 수치를
   사실로 배운다. 가상 종목으로 바꾸고 `node scripts/gen-seed.mjs` → 시드 재적용.
   종목명 방식(완전 창작 / 패러디 / 기호명) **미정**
2. **관리자 비밀번호 변경** — 개발용 값이 그대로다. `private.set_admin_secret()` + `.env` 동시 변경
3. **테스트 흔적 제거** — `TEST-01`·`TIGER-03` 조 삭제, [게임 리셋] 리허설.
   **개발 DB가 곧 대회 DB다**
4. **배포** — 어디에 올릴지 미정 (Vercel 등). 교육장 와이파이에서 Supabase 접속 가능한지 확인 필요
5. **실기기 테스트** — 실제 태블릿에서 그리기·터치·회전. 지금은 헤드리스 브라우저 검증만

- **[잠정] 결정 확인** — "3단계 지시서"와 UI 명세를 받지 못해 직접 설계한 부분이 있다.
  문서 도착 시 대조 필요: 실시간 신호 방식, 주문서 패널·힌트 카드 UI, 배분 제안 UI
- **자금 규칙 확정** — 매도 대금을 매수 자금으로 인정하는 규칙이 잠정. `order_funds_ok()` 한 줄
- **순위 상시 노출 유지 여부** — 팀 결정 대기
- **봉 주기 실데이터화** — 일/주/월/년이 전부 같은 구간. 알려진 껍데기
- **파일 정리** — `index.css` 1,500줄+ 분리
- **동시 접속 규모** — 조 개수 미정

## 알려진 한계

1. **관리자 비밀이 브라우저 번들에 들어간다** — `VITE_ADMIN_PASSWORD`는 빌드 시 인라인된다.
   학생이 `/admin` 소스를 뜯어보면 알 수 있다. 진짜 분리는 Supabase Auth + service role 필요
2. **참가 코드를 아는 사람은 그 조로 로그인할 수 있다** — 코드 기반 인증의 본질
3. **힌트 Realtime 직접 구독 불가** — RLS 대신 RPC로 격리해서. signals 우회로 해결했으나
   신호 → 재조회라 약간의 지연이 있다
4. **개발 DB = 대회 DB** — 분리된 개발 프로젝트가 없다
